# Local Keycloak Login + Admin Dashboard

This build keeps AI Speaker Notes local while authentication uses the existing Keycloak realm:

`https://identity-iot.lensalingkungantech.com/realms/aispeaker`

There is no application-owned Keycloak login screen in front of it. When authentication is required, the browser is redirected straight to Keycloak.

## Current flow

```text
http://127.0.0.1:8001/
        -> Keycloak when not signed in
        -> /auth/callback
        -> AI Speaker Notes dashboard

http://127.0.0.1:8001/admin
        -> Keycloak when not signed in
        -> /auth/callback
        -> /admin when the account is an administrator
        -> 403 when the account is authenticated but is not an administrator
```

`/login` remains only as a compatibility URL. In a Keycloak deployment it immediately starts the same Keycloak OIDC flow and does not render the old custom login page.

## Admin features included

- List Keycloak users and merge them with application PostgreSQL metadata.
- Search users by name, username, or email.
- Create Keycloak users.
- Edit username, email, first name, last name, and email verification state.
- Ban and unban accounts.
- Delete a Keycloak account and clean the user's application data.
- View the application database record for each user.
- View every PowerPoint job stored for the user, including filename, status, timestamps, input/output size, language, audience, depth, vision/text mode, model, tokens, estimated cost, and error information when present.
- Block banned/deleted users locally even if an older application session cookie still exists.
- CSRF protection for admin mutations.
- Separate server-side Keycloak service account for user administration. Its secret is never sent to browser JavaScript.

## 1. Fix `redirect_uri` in Keycloak once

The exact callback generated by this local build is:

```text
http://127.0.0.1:8001/auth/callback
```

In Keycloak, open realm `aispeaker` -> Clients -> `ai-speaker-notes` and configure at least:

```text
Valid Redirect URIs
http://127.0.0.1:8001/auth/callback

Web Origins
http://127.0.0.1:8001

Valid Post Logout Redirect URIs
http://127.0.0.1:8001/*
```

If you intentionally use `localhost` instead of `127.0.0.1`, also add:

```text
http://localhost:8001/auth/callback
http://localhost:8001
http://localhost:8001/*
```

If Keycloak displays `Invalid parameter: redirect_uri`, the callback sent by the app is not allowed by this client. Also make sure `.env` contains exactly:

```text
PUBLIC_BASE_URL=http://127.0.0.1:8001
```

The browser address and `PUBLIC_BASE_URL` must agree. Do not use port `8000` in `.env` while running the application on port `8001`.

Keep Client authentication enabled and copy the existing `ai-speaker-notes` client secret into the local `.env`.

## 2. Give the administrator access

Preferred approach: create/assign a realm role named:

```text
admin
```

and assign it to the administrator account.

For local bootstrap only, you can instead put the Keycloak `preferred_username` into:

```text
```

The Keycloak role is the preferred production mechanism.

## 3. Create the admin service-account client

Create a second confidential client in the same `aispeaker` realm:

```text
Client ID: ai-speaker-admin
Client authentication: ON
Standard flow: OFF
Direct access grants: OFF
Service accounts roles: ON
```

Assign these `realm-management` roles to its service account:

```text
query-users
view-users
manage-users
```

Then copy its secret into:

```text
KEYCLOAK_ADMIN_CLIENT_SECRET=...
```

This client is used only by the FastAPI backend for create/edit/ban/unban/delete operations.

## 4. Local environment

Copy the provided template:

```powershell
Copy-Item .\deploy\admin-local.env.example .\.env
```

Fill these values:

```text
SESSION_SECRET=...
KEYCLOAK_CLIENT_SECRET=...
KEYCLOAK_ADMIN_CLIENT_SECRET=...
```

Generate a local session secret with:

```powershell
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

Do not commit `.env`.

## 5. Start local PostgreSQL and the app

Shortest Windows command:

```powershell
.\scripts\run-admin-local.ps1
```

The script starts the local PostgreSQL container, creates/updates the Python environment, and starts FastAPI on port `8001`.

Open the application directly:

```text
http://127.0.0.1:8001/
```

Or go straight to the admin console:

```text
http://127.0.0.1:8001/admin
```

Both routes go straight to Keycloak when there is no valid application session.

## 6. Later: connect to the VPS PostgreSQL database

The application domain is not the PostgreSQL address. When the VPS database is ready, only change `DATABASE_URL` to the PostgreSQL connection string supplied by the server/cPanel/VPS setup, for example:

```text
DATABASE_URL=postgresql+psycopg://aispeaker_user:<database-password>@127.0.0.1:5432/aispeaker
```

If PostgreSQL runs in another private host/container, use that private hostname instead of `127.0.0.1`.

Do not expose PostgreSQL port `5432` publicly unless there is a specific operational need. Prefer localhost/private networking and firewall rules.

The application already uses the stable Keycloak `sub` as its user ownership key, so switching from local PostgreSQL to the VPS PostgreSQL does not require rewriting the admin UI or authentication flow. Production data migration should be done explicitly when that stage begins.

## Admin authorization (role-only)

Admin access is granted **only** when the signed Keycloak token contains the role configured by `ADMIN_ROLE` (default: `admin`). Username and subject allowlists are not supported. Assign the `admin` realm role (or the `admin` client role on `ai-speaker-notes`) to the intended administrator in Keycloak, then sign out and sign in again so a fresh token is issued.


## Local admin data integration update

- The user-facing app and `/admin` use the same `DATABASE_URL`. Presentation history is stored in `jobs`; persistent AI chat is stored in `chat_threads` and `chat_messages`; login/application users are stored in `users`.
- `/admin` user detail now reads both presentation jobs and saved chat threads/messages for that Keycloak user subject.
- Admin access is granted only when the signed Keycloak token contains the configured `ADMIN_ROLE` (default `admin`). Username-based admin bypasses are not used.
- The local launcher can reuse the existing `KEYCLOAK_CLIENT_SECRET` from a sibling `ai-speaker-notes-mvp/.env` when the new `.env` still contains a placeholder. It never prints the secret.
- If Keycloak rejects the OIDC client credentials, the callback now returns a clear configuration error instead of an unhandled 500 traceback.


## Jika callback gagal dengan `token is not yet valid (iat)`

Ini berarti token Keycloak sudah berhasil diterbitkan, tetapi jam Keycloak/VPS sedikit lebih maju daripada jam komputer lokal. Paket ini memberi toleransi clock skew 60 detik (`KEYCLOAK_CLOCK_SKEW_SECONDS=60`) sambil tetap memvalidasi signature, issuer, audience, dan expiry.

Prioritas tetap sinkronkan jam Windows/VPS. Untuk testing lokal, bila drift masih lebih besar, set sementara `KEYCLOAK_CLOCK_SKEW_SECONDS=120`, restart aplikasi, lalu mulai login baru dari `/admin` (jangan refresh URL `/auth/callback` lama).

### Unauthorized administrator account
If a valid Keycloak account signs in through `ai-speaker-admin-login` but does not have the configured `admin` role, the application redirects to `/admin/unauthorized` instead of issuing an admin session. The recovery button clears the local application session, requests Keycloak SSO logout for the admin client, and returns to `/admin` so another administrator account can sign in.

## v17: Separate application activity database

The admin process keeps `DATABASE_URL` for its own local session/audit data. To read processed PowerPoint jobs and saved chat from the real AI Speaker Notes PostgreSQL database, set:

```env
APPLICATION_DATABASE_URL=postgresql+psycopg://<user>:<password>@127.0.0.1:<tunnel-port>/<database>
```

For a remote VPS database, prefer an SSH tunnel rather than opening PostgreSQL to the public Internet. The application data connector is read-only in the admin dashboard code path and supports the original v1 `users` schema without applying migrations.

Admin sign-out uses `/api/v1/auth/admin/logout`, which logs out `ai-speaker-admin-login` and clears all local OIDC state before the next sign-in.

## External activity database / SSH tunnel resilience
When `APPLICATION_DATABASE_URL` points to a local SSH-forwarded port (for example `127.0.0.1:55432`), keep the SSH tunnel open while using the admin dashboard. A recommended tunnel command is:

```powershell
ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -o ServerAliveCountMax=3 -L 55432:127.0.0.1:5432 root@YOUR_VPS
```

From v20 onward, a temporary tunnel outage does not stop the admin application from starting. The application activity reader retries when later requests arrive after the tunnel is restored.
